REGISTRATION

frontend sends email, username, psw, language
  ↓
server check and sends a verification email
  ↓
user clicks email link
  ↓
frontend route opens
  ↓
frontend extracts token
  ↓
frontend calls backend
  ↓
backend verifies token
  ↓
frontend shows success/error page
  ↓
fronend redirects to login page

Registration rules:
  Username: 3-20 chars, allowed chars: [a-z, A-Z, 0-9, '_', '.'],
    excluded reserver usernames: [admin, support, api, system, root],
    In db: trimmed, lowercased and UNIQUE
  Psw: 8-128 chars, exlcluded popular passwords, In db: hashed
  Email: max 100 chars, In db: trimmed, lowercased and UNIQUE

SECURITY NOTE:
  Unlike password reset, registration DOES expose email/username existence
  when returning errors (e.g., "Email already in use", "User already exists").
  This is a deliberate UX tradeoff - clear error messages help legitimate users
  understand why registration failed, while email enumeration during registration
  is considered a lower risk (users typically know their own email exists).
  Email enumeration is prevented in password reset where it's more critical.


LOGIN

frontend sends username, psw
  ↓
server check if profile exist  → error
  ↓
server check if not verified  → error and issue new verification token (401 + EMAIL_NOT_VERIFIED)
  ↓
server check the psw  → error
  ↓
issue jwt and refresh tokens


PASSWORD RESET

frontend call /auth/forgot-passwords with email
  ↓
server checks if email exists and is verified (silently, no error thrown)
  ↓
if email exists and verified: generate and issue new password reset token
  ↓
always returns success (even if email doesn't exist or not verified)
  ↓
** SECURITY: Always returns same success message to PREVENT EMAIL ENUMERATION ATTACKS **
  ↓
user clicks on email and it's sent to frontend reset page (if email was valid)
  ↓
frontend sends token + new psw to 'auth/reset-password'
  ↓
server DOESN'T check for email verification
  ↓
!! PSW RESET DOESN'T VERIFY EMAIL !! it could but for semplcity it doesn't
  ↓
server revokes jwt and refresh tokens
  ↓
frontend shows success/error page
  ↓
fronend redirects to login page
